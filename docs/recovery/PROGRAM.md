**Product direction and decisions**

Entities should let a writer find, link, and create meaningful entities without leaving the sentence. Preserve `@` for entities, `:` for symbols, `/` for actions, configurable provider instances, and synchronous suggestion retrieval. **Architecture contracts**

1. **Configured source identity.** `providerTypeID` identifies implementation type; persisted `providerInstanceId` identifies one configured source. IDs survive reorder, labels, reload, and restart. The configuration add/migration boundary assigns them once. Provider default factories remain ID-free and return fresh nested structures. Runtime reconstruction does not invent identity.
2. **Settings ownership.** A plugin-owned store normalizes versioned data, preserves unknown fields/providers, exposes immediate canonical updates by ID, and serializes persistence. UI receives independent drafts; conflicting stale drafts require visible recovery instead of silently replacing newer data. Deleted IDs cannot be resurrected by stale callbacks. Preserve a recoverable, Git-ignored original-data copy before the first schema-changing write. Malformed/future data disables every persistence path, including UI edits, retry, flush, and unload, until safe recovery is established. The storage boundary must expose actual read, parse, and write failures: inspected Obsidian versions swallow errors inside `loadData`/`saveData`. Ordinary disable/re-enable must hand off pending persistence between plugin instances before the successor reads settings. Flush/retry behavior is explicit; no promise that Obsidian awaits asynchronous unload or protects against process termination.
3. **Suggestion meaning.** Retain familiar labels, but distinguish real file targets, deliberate unresolved links, literal text, and actions. Real targets preserve the file and optional alias; native link generation uses the source note and user preferences. Deduplication uses target/alias or action identity. Identical labels may remain visible with useful path/source context.
4. **Action outcomes.** An editor-independent creation operation returns the actual file, cancellation, or failure, with explicit collision behavior. It owns neither modal prompts nor editor transactions nor CLI discovery/IDs. The insertion coordinator catches synchronous/async errors, prevents duplicate execution, and validates editor, source-document revision, range, expected content, and lifecycle before applying a delayed result. Unload, document replacement, source deletion, or editor reuse invalidates pending insertion. A created file remains discoverable even if later insertion is cancelled. Intentional unresolved-date fallback must not masquerade as successful creation. Preserve the existing creation-recipe promise that a missing/empty configured folder means vault root, including canonical `/` saved by the existing folder picker. Actions without a destination setting resolve Obsidian's default against the captured source before awaiting; root and default are separate requests. Legacy Core-engine records remain preserved with an honest unsupported state; opening/saving their modal must not write an invalid empty engine. Implementing a new Core engine is deferred.
5. **Cache/lifecycle.** Cache by configured provider and trigger, with explicit query dependence and bounded entries. Invalidate on configuration/data/lifecycle changes and retain a limited freshness fallback where integration indexes lack reliable events. Catch failures during construction, ordinary suggestions, and creation suggestions independently. Optional integrations can become available after startup.
6. **Integration boundaries.** Providers do not perform network/shell work during lookup. Parsing and naming are separate from note creation. Actual Templater 2.11.1/2.25.0 evidence reproduces stale native insertion and shared-configuration contamination under overlapping runs. Neither an Entities-only queue nor a final configuration check isolates external native runs. Keep Entities insertion explicitly unavailable until a reviewed integration supports isolated rendering and a guarded commit with properties/cursor/hooks parity. The manual native command remains the user's separate operation, without an Entities safety guarantee. Creation outcomes certify returned file identity and honest status, not isolation of arbitrary native template scripts.

The editor coordinator uses immediate public editor-change events to detect delivered edit/undo updates, observed activation changes, and final live file/editor/document/selection checks. Native activation events are debounced: a same-task programmatic switch away/back can collapse before notification, so do not promise detection of every unobservable activation history. No private setter interception or arbitrary timer substitutes for this boundary. Modal blur and unrelated layout changes alone do not invalidate actions. Helper transformations preserve existing created metadata and add it only when enabled and absent.

R4b keeps entry validity separate from operation validity: consume the displayed result epoch once, then retain the pending operation across ordinary menu close, fresh retrieval and background data events. Registry/provider replacement and unload still cancel it. Public CodeMirror bindings must handle initially absent editor information and seed the selected editor's focus identity, so returning from a modal does not falsely cancel work. Typed outcomes replace editor-bearing callbacks; only the coordinator commits one synchronous editor transaction after final checks. A confirmed creation remains a creation even if the returned file disappears before insertion. The required public editor APIs exist in 1.7.2; this packet does not change the support floor. STATUS records the exact limited live checks separately from full lifecycle/runtime acceptance.

R4c follows the host’s recognized code/link spans using the same public live binding and native syntax tree, with one documented native-label-anchored unfinished Markdown destination exception. It neither implements a second parser nor promises universal malformed-Markdown exclusion. Missing, stale or incomplete syntax suppresses only that request; later normal requests may retry. Escape dismissal belongs to the exact live editor/file/binding phrase, never every menu close. Dismiss the current continuation even if rendered rows lag behind native typing. Retain only a validated displayed binding for composing-Escape protection during delayed popup cleanup; stale bindings must not consume unrelated keys.

**How delegated work is controlled**

- Every significant task gets the product intent, verified base, allowed files, contract, exclusions, acceptance cases, predecessor PRs, and a request to return a PR URL and exact head SHA. It owns an isolated worktree and never merges itself.
- Keep at most two substantial implementation lanes active while the core contracts change: one runtime lane and one independent tooling/validation lane. Use short-lived sub-agents for narrow repros, adapter research, and focused fixes.
- The owner retains architecture, compatibility, feature ordering, UX decisions, and release acceptance. Delegate implementation, not these decisions. If a task needs broader scope, update the brief before it expands.
- PR readiness triggers a fresh reviewer who did not author the changes. Settings migration and async editor changes receive both a code/state-transition review and a runtime/UX review where applicable. Reviews identify exact head SHA, actionable findings, reproductions, and test gaps.
- Route findings back to the implementation task. After fixes, review the changed head and rerun relevant checks. Do not accept stale review results, green tests that mock away the failing boundary, or a worker's self-review as final approval.
- The owner checks the complete diff, accepted scope, current CI, unresolved discussions, and regression evidence before merging the reviewed revision. Integrate one core PR at a time; verify the resulting master before dispatching its dependent packet.
- At each handoff the coordinator updates STATUS.md with task ID, branch/worktree, PR/head, validation evidence location, reviewer/findings, exact reviewed revision and resulting master SHA, accepted decisions, blockers, and next owner/action. Keep one maintained program rather than accumulating contradictory plans. Completion reports must be sent back to the coordinator task so idle coordination resumes.
